# Официальный портал Комаринской Федерации

Информационный портал RP-проекта: новости, электронная правовая база, материалы Думы КФ, кодексы, сведения об органах власти и международных отношениях.

Разработчик: KALTEN Technologies. Портал не является государственным органом Комаринской Федерации, если такой статус не установлен отдельно.

## Две версии

Проект содержит две независимые версии с одинаковым оформлением:

| Версия | Файл | Назначение |
| --- | --- | --- |
| Основная | `src/` | React + TypeScript + Vite, данные и авторизация Supabase, публикация на GitHub Pages |
| Автономная | `local/index.html` | Один HTML-файл без сети, сборки и Supabase; открывается через `file://` в Microsoft Edge |

Автономная версия предназначена для демонстрации интерфейса. Встроенный демонстрационный редактор изменяет данные только в памяти открытой страницы. После перезагрузки восстанавливается исходный набор.

## Автономная версия

Откройте `local/index.html` двойным щелчком в Microsoft Edge или перетащите файл в окно браузера.

- интернет, сервер, Node.js и Supabase не требуются;
- все стили, скрипты и данные встроены в файл;
- внешние CDN, веб-шрифты и обязательные сетевые запросы отсутствуют;
- работают поиск, фильтры, маршруты, мобильное меню и демонстрационный редактор;
- изменения в редакторе исчезают после перезагрузки;
- все материалы являются демонстрационными и не считаются официальными документами.

## Основная версия локально

Требуется Node.js 22.12 или новее (Vite 8 также поддерживает Node.js 20.19+).

```bash
npm ci
npm run dev
```

Dev-сервер по умолчанию открывается по адресу `http://localhost:5173/kf-portal/`, потому что базовый путь production-сборки равен `/kf-portal/`.

Файл `package-lock.json` включён в проект и фиксирует версии зависимостей. Команда `npm ci` воспроизводит их без изменения lock-файла. Для первого добавления зависимости можно использовать `npm install`.

Проверка типов и production-сборка:

```bash
npm run typecheck
npm run build
npm run preview
```

Если Supabase не настроен, публичные разделы покажут пустые состояния, а служебная панель — предупреждение. Это ожидаемое поведение: без публичных параметров подключения приложение не обращается к базе.

## Настройка Supabase

1. Создайте проект в Supabase.
2. В SQL Editor последовательно выполните файлы:
   - `supabase/migrations/202610230001_initial_schema.sql`;
   - `supabase/migrations/202610230002_rls.sql`.
3. При необходимости выполните `supabase/seed.sql`. Он добавляет только демонстрационные материалы с пометкой `is_demo = true`.
4. Создайте сотрудника в разделе Authentication. Самостоятельная регистрация не выдаёт административные права.
5. Назначьте роль в таблице `profiles`:

```sql
update public.profiles
set role = 'admin'
where id = (
  select id from auth.users where email = 'admin@example.com'
);
```

Замените `admin@example.com` на фактический адрес. Роли: `user`, `editor`, `duma`, `admin`.

6. Создайте `.env` на основе `.env.example`:

```dotenv
VITE_SUPABASE_URL=https://YOUR-PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR-PUBLIC-ANON-KEY
```

Используется только публичный `anon key`, защищённый политиками RLS. Ключ `service_role` нельзя добавлять в `.env`, клиентский код, репозиторий, GitHub Variables или публичную сборку.

Подробные инструкции: `docs/DEPLOYMENT.md` и `docs/SECURITY.md`.

## Публикация на GitHub Pages

1. Создайте репозиторий на GitHub и загрузите файлы проекта через веб-интерфейс. Если скрытый каталог `.github` не загрузился, создайте `.github/workflows/deploy.yml` через **Add file → Create new file**.
2. Откройте **Settings → Pages** и выберите источник **GitHub Actions**.
3. Откройте **Settings → Secrets and variables → Actions → Variables** и добавьте:
   - `VITE_SUPABASE_URL`;
   - `VITE_SUPABASE_ANON_KEY`.
4. Отправьте изменения в ветку `main` или запустите workflow вручную на вкладке **Actions**.
5. После сборки адрес сайта отображается в окружении `github-pages` и в разделе **Settings → Pages**.

Для обычного репозитория базовый путь автоматически равен `/<имя-репозитория>/`. Для сайта пользователя или организации вида `<username>.github.io` измените в workflow:

```yaml
VITE_BASE: /
```

При использовании собственного домена базовый путь также должен быть `/`. Подробнее: `docs/DEPLOYMENT.md`.

## Принципы данных

- Черновики новостей не отображаются в публичной ленте.
- Для документов раздельно хранятся даты принятия, опубликования и вступления в силу.
- Демонстрационные записи помечаются `is_demo` и подписываются в интерфейсе.
- Результаты голосований публикуются только при наличии подтверждённого источника.
- Персональные данные должностных лиц не публикуются без официального подтверждения.
- Санкции и составы правонарушений не выдумываются: до согласования используются шаблоны без конкретных наказаний.
