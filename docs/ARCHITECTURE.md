# Архитектура портала

## Обзор

Основная версия — одностраничное приложение на React 18, TypeScript и Vite. Оно публикуется как статический сайт на GitHub Pages и обращается к Supabase напрямую из браузера. Отдельного серверного API нет.

Автономная версия `local/index.html` не использует модули, сборку, сеть или Supabase. Это один документ с inline CSS, JavaScript и демонстрационным набором данных.

## Технологический стек

- React 18.3 и React DOM.
- React Router 7 с `BrowserRouter`.
- TypeScript 5.9, strict-режим.
- Vite 8.
- `@supabase/supabase-js` 2.x: база, Auth и RLS (точная версия зафиксирована в `package-lock.json`).
- Обычный CSS без UI-фреймворков и внешних шрифтов.

## Маршруты

| Маршрут | Назначение |
| --- | --- |
| `/` | Главная: главная новость, лента, объявления, документы |
| `/news` | Лента новостей с поиском, категорией, периодом и сортировкой |
| `/news/:id` | Публикация |
| `/duma` | Законопроекты, повестки и протоколы |
| `/duma/bills/:id` | Карточка законопроекта, история и голосования |
| `/legislation` | Правовая база с фильтрами |
| `/legislation/:id` | Документ, даты, история и связанные акты |
| `/criminal-code` | Уголовный кодекс по категориям |
| `/criminal-code/:id` | Статья Уголовного кодекса |
| `/administrative-code` | Административное законодательство |
| `/administrative-code/:id` | Статья административного кодекса |
| `/bodies` | Органы власти |
| `/bodies/:slug` | Карточка органа |
| `/international` | Международные документы |
| `/about` | О портале и принципах публикации |
| `/search` | Единый поиск |
| `/admin` | Служебная панель: вход и управление новостями |
| `*` | Страница 404 |

Автономная версия использует те же маршруты в формате hash: `#/news`, `#/legislation/d3` и так далее. Для демонстрационного редактора добавлены `#/demo-admin` и `#/demo-admin/edit/:id`.

## Слои приложения

```text
src/
├── main.tsx                 # монтирование React
├── App.tsx                  # маршруты
├── components/
│   ├── Layout.tsx           # шапка, навигация, поиск, подвал
│   └── ui.tsx               # PageHeader, Badge, Notice, EmptyState и др.
├── lib/
│   ├── supabase.ts          # клиент Supabase и проверка конфигурации
│   ├── format.ts            # даты, подписи, статусы, тон бейджей
│   └── useAsync.ts          # загрузка данных и сообщения об ошибках
├── pages/                   # страницы по маршрутам
├── services/
│   ├── content.ts           # публичные запросы и поиск
│   └── admin.ts             # Auth, профиль, CRUD новостей
├── styles/global.css        # дизайн-система
└── types/content.ts         # доменные типы
```

Компоненты не содержат SQL и не работают с ключами напрямую. Доступ к данным сосредоточен в `services`.

## Поток данных

1. Страница вызывает функцию из `services/content.ts` или `services/admin.ts`.
2. `lib/supabase.ts` возвращает singleton-клиент, созданный из `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.
3. Запрос уходит в Supabase REST под ролью `anon` или `authenticated`.
4. RLS ограничивает строки и операции.
5. Компонент отображает данные, пустое состояние или ошибку.

Если переменные окружения не заданы, `isSupabaseConfigured` равен `false`. Публичные страницы показывают пустые состояния, а админпанель — предупреждение вместо формы входа.

## Аутентификация и роли

Используется Supabase Auth с email и паролем. Профиль создаётся триггером `handle_new_user` после регистрации или создания пользователя администратором.

| Роль | Возможности |
| --- | --- |
| `user` | Только публичный просмотр |
| `editor` | Публичный просмотр, управление новостями, правовыми документами, кодексами и международными материалами |
| `duma` | Публичный просмотр, управление законопроектами, событиями, голосованиями и заседаниями |
| `admin` | Полный доступ, включая профили, органы власти и журнал действий |

Роль хранится только в `public.profiles` и не берётся из пользовательских метаданных. Клиентский интерфейс скрывает недоступные действия, но окончательная проверка выполняется в RLS.

## Схема данных

### Основные таблицы

- `profiles` — профиль пользователя и роль.
- `news_posts` — новости, статусы публикации и автор.
- `legislation_documents` — нормативные акты и история редакций.
- `code_articles` — статьи Уголовного и Административного кодексов.
- `bills` — законопроекты.
- `bill_events` — история рассмотрения законопроекта.
- `votes` — опубликованные результаты голосований.
- `duma_sessions` — повестки и протоколы.
- `gov_bodies` — органы власти.
- `intl_documents` — договоры, соглашения, заявления и переговоры.
- `audit_log` — журнал изменений новостей.

### Связи

- `news_posts.created_by → profiles.id`;
- `bill_events.bill_id → bills.id` с каскадным удалением;
- `votes.bill_id → bills.id` с каскадным удалением;
- `audit_log.actor_id → profiles.id`;
- `profiles.id → auth.users.id` с каскадным удалением.

### Особенности полей

- `is_demo` помечает демонстрационные материалы.
- `published` у голосований, заседаний и международных документов отделяет черновик от публикации.
- `status` у новостей: `draft`, `published`, `archived`.
- `status` у нормативных актов и статей кодексов: `draft`, `in_force`, `amended`, `suspended`, `repealed`, `cancelled`.
- `status` у законопроектов: от `draft` до `published` и `void`.
- `history` хранится как JSON-массив записей `{ "date": "...", "note": "..." }`.
- `related_numbers` и `related` хранятся как текстовые массивы.
- Даты принятия, опубликования и вступления в силу — отдельные поля.

## Безопасность на уровне базы

RLS включён для всех таблиц. Публичный `anon` читает только разрешённые строки. Запись доступна только ролям через security definer-функции `can_manage_news`, `can_manage_duma`, `can_manage_content` и `is_admin`.

`audit_log` заполняется триггером на `news_posts` и доступен только администраторам. Подробнее: `docs/SECURITY.md`.

## Автономная версия

`local/index.html` содержит:

- собственный CSS, дополняющий основную дизайн-систему;
- набор данных в JavaScript;
- hash-маршрутизатор;
- поиск и фильтры на стороне клиента;
- демонстрационный редактор новостей в памяти;
- сброс набора без записи на диск.

Сеть не используется. В файле нет `http://`, `https://`, CDN, веб-шрифтов и обязательных внешних ресурсов. Внешний вид и тексты соответствуют основной версии, но данные независимы.

## GitHub Pages и SPA

GitHub Pages не отдаёт `index.html` для вложенных маршрутов. `vite.config.ts` добавляет плагин, который:

- восстанавливает путь из параметра `?/path` при загрузке приложения;
- создаёт `404.html` с перенаправлением на маршрут SPA;
- создаёт `.nojekyll`, чтобы GitHub Pages не обрабатывал файлы через Jekyll.

Базовый путь задаётся `VITE_BASE`. Для репозитория по умолчанию используется `/kf-portal/`; workflow подставляет имя репозитория. Для сайта пользователя, организации или собственного домена нужен `/`.

## Ограничения

- Нет серверного API и фоновых задач.
- Нет загрузки файлов и изображений.
- Нет самостоятельной выдачи ролей.
- Нет публичной регистрации с административными правами.
- Нет автоматической генерации юридических текстов и санкций.
- Админпанель управляет только новостями; остальные разделы наполняются через SQL или будущие служебные экраны.
