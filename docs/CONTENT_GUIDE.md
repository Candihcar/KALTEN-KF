# Руководство по материалам

## Общие правила

1. Публикуйте только проверенные сведения.
2. Не выдавайте проект, предложение или демонстрационный пример за действующий акт.
3. Указывайте источник, орган и дату для каждого официального материала.
4. Разделяйте дату принятия, дату опубликования и дату вступления в силу.
5. Не придумывайте номера документов, результаты голосований, санкции и должностных лиц.
6. Демонстрационные записи помечайте `is_demo = true`.
7. Проверяйте текст перед публикацией: черновик не виден в публичной ленте новостей.
8. Не публикуйте персональные данные без подтверждённого основания.

## Новости

### Категории

| Код | Подпись |
| --- | --- |
| `state` | Государство |
| `government` | Правительство |
| `duma` | Дума |
| `legislation` | Законодательство |
| `international` | Международные отношения |
| `security` | Безопасность |
| `statements` | Официальные заявления |
| `announcements` | Объявления |

### Статусы

| Код | Значение |
| --- | --- |
| `draft` | Черновик; не виден публично |
| `published` | Опубликовано; видно в ленте |
| `archived` | Архив; не виден публично |

### Поля

- `title` — заголовок до 200 символов;
- `summary` — краткое описание до 600 символов;
- `body` — полный текст, абзацы разделяются пустой строкой;
- `category` — одна из категорий выше;
- `author` — автор или орган, например «Пресс-служба Правительства КФ»;
- `status` — статус публикации;
- `is_demo` — признак демонстрационного материала;
- `published_at` — дата публикации; при отсутствии интерфейс использует дату создания.

### Порядок публикации

1. Создайте черновик.
2. Проверьте заголовок, лид и текст.
3. Сверьте категорию, автора и дату.
4. Убедитесь, что в материале нет неподтверждённых санкций и персональных данных.
5. Поставьте `is_demo`, если это пример.
6. Переведите в `published`.
7. Откройте публичную ленту и карточку новости, проверьте отображение.

Публичная лента показывает только `published`. Черновик и архив доступны сотрудникам с правом управления новостями.

## Правовая база

### Типы документов

- Конституция КФ;
- Уголовный кодекс;
- Административный кодекс;
- законы КФ;
- постановления;
- указы;
- решения Думы;
- международные договоры;
- отдельные акты.

### Статусы

| Код | Подпись | Когда использовать |
| --- | --- | --- |
| `draft` | Проект | Текст ещё не принят |
| `in_force` | Действует | Акты применяются |
| `amended` | Изменён | Есть действующая редакция с изменениями |
| `suspended` | Приостановлен | Действие приостановлено |
| `repealed` | Утратил силу | Заменён или отменён |
| `cancelled` | Отменён | Отменён органом или решением |

### Обязательные сведения

- `doc_number` — номер или обозначение;
- `title` — официальное название;
- `doc_type` — тип;
- `authority` — принявший орган;
- `category` — категория для фильтра;
- `status` — юридический статус;
- `adopted_on` — дата принятия;
- `published_on` — дата официального опубликования;
- `effective_on` — дата вступления в силу;
- `revision` — редакция;
- `summary` — краткое содержание;
- `body` — полный текст;
- `related_numbers` — связанные номера;
- `history` — история изменений в формате дата/примечание.

Если дата неизвестна, оставьте поле пустым. Не подставляйте предполагаемую дату.

## Кодексы

### Уголовный кодекс

- `code_kind = 'criminal'`;
- `article_number` — номер статьи;
- `title` — название;
- `part` — часть или глава;
- `category` — раздел для фильтра;
- `description` — диспозиция;
- `sanction` — санкция;
- `notes` — примечания;
- `related` — связанные статьи;
- `status` — статус;
- `effective_on` — дата вступления в силу;
- `history` — изменения.

### Административный кодекс

Те же поля, но `code_kind = 'administrative'`.

Санкции и составы нельзя придумывать. Если текст не согласован, используйте формулировку «проект» и оставьте `sanction` пустым либо явно пометьте материал как демонстрационный. Не переносите реальные нормы других государств без решения редакции.

## Дума КФ

### Законопроекты

Поля:

- `number` — номер;
- `title` — название;
- `summary` — суть;
- `status` — стадия;
- `initiator` — инициатор;
- `submitted_on` — дата внесения;
- `related_law_number` — номер принятого закона;
- `is_demo`.

Статусы: `draft`, `submitted`, `under_review`, `voting`, `adopted`, `rejected`, `revision`, `signed`, `published`, `void`.

История рассмотрения хранится в `bill_events`: дата, заголовок, описание. События отображаются в карточке законопроекта.

### Голосования

Поля:

- `bill_id` — законопроект;
- `voted_on` — дата;
- `title` — вопрос;
- `for_count`, `against_count`, `abstain_count` — результаты;
- `published` — публикация;
- `source_note` — источник.

Публично показываются только голосования с `published = true`. Не публикуйте предполагаемые результаты и не заполняйте числа без подтверждённого протокола.

### Заседания

- `kind = 'agenda'` — повестка;
- `kind = 'protocol'` — протокол;
- `number` — номер;
- `title` — название;
- `session_date` — дата;
- `body` — содержание;
- `published` — публикация.

Протокол не публикуется до официального оформления. Повестка может быть опубликована заранее, если это предусмотрено регламентом.

## Органы власти

- `slug` — стабильный латинский идентификатор;
- `name` — официальное название;
- `kind` — тип органа;
- `summary` — краткое описание;
- `description` — полное описание;
- `structure` — структура;
- `contacts` — официальные контакты;
- `sort_order` — порядок вывода.

Типы: `head`, `government`, `duma`, `judicial`, `law_enforcement`, `agency`.

Не добавляйте имена должностных лиц, личные телефоны и адреса без подтверждения. Контакты должны быть официальными и публичными.

## Международные материалы

Типы: `treaty`, `agreement`, `statement`, `negotiation`.

Поля:

- `title` — название;
- `kind` — тип;
- `country` — страна или сторона;
- `signed_on` — дата подписания;
- `status` — состояние;
- `summary` — краткое описание;
- `body` — текст;
- `published` — публикация;
- `is_demo`.

Не публикуйте проект договора как действующий. Для переговоров указывайте стадию и не приписывайте сторонам обязательства, которых нет в подтверждённом источнике.

## Демонстрационные материалы

Признак `is_demo` обязателен для:

- примеров интерфейса;
- тестовых новостей;
- шаблонных статей кодексов;
- учебных законопроектов;
- вымышленных международных документов.

Демонстрационные записи должны быть визуально помечены. Их нельзя использовать как основание для RP-санкций или официальных решений.

Перед запуском рабочего портала решите, оставлять ли seed. Если он остаётся, проверьте, что все записи имеют `is_demo = true`, а результаты голосований и протоколы отсутствуют.

## Редакционный процесс

1. Автор готовит черновик.
2. Редактор проверяет факты, даты и формулировки.
3. Для правовых актов отдельно сверяются статус и дата вступления в силу.
4. Для Думы проверяются стадия законопроекта и наличие протокола.
5. Публикация переводится в `published`.
6. Сотрудник открывает публичную страницу и проверяет карточку.
7. Изменения фиксируются в `audit_log` автоматически.

## Проверка перед публикацией

- [ ] Заголовок точно отражает содержание.
- [ ] Указан орган или автор.
- [ ] Даты разделены и проверены.
- [ ] Номер документа совпадает с источником.
- [ ] Статус соответствует стадии.
- [ ] Нет вымышленных санкций и результатов голосований.
- [ ] Нет персональных данных без основания.
- [ ] Демонстрационный материал помечен.
- [ ] Ссылки и связанные документы корректны.
- [ ] Публичная карточка открывается и отображается без ошибок.
